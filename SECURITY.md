# Security Policy

## Supported versions

WireLens is in planning and architecture and has no released or supported application version yet. This policy will be updated before the first release.

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting for this repository when available. If that channel is unavailable, contact the repository owner privately through their GitHub profile and request a secure reporting channel. Do not disclose the issue publicly until a coordinated fix and disclosure plan exist.

Include the affected commit or version, impact, reproduction conditions, and a minimal safe proof of concept. Never send real packet captures containing credentials, personal data, customer traffic, private addresses, or proprietary topology unless a secure channel and handling agreement have been established.

## Capture-data safety

Packet captures are untrusted binary input and may contain highly sensitive content. Public reports and tests must use synthetic or explicitly redistributable fixtures with documented provenance. Remove or replace payloads, identifiers, addresses, names, and secrets where applicable.

Security reports will be acknowledged as soon as reasonably possible. Timelines depend on severity and project maturity; maintainers will communicate status through the private reporting channel.
